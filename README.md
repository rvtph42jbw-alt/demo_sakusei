# まちの安全マップ

地域の小さな気づきを、まちの安心へ。地図を中心に、検索・危険箇所の詳細・通報・防災・お気に入りを利用できるWebアプリです。Feltの緑系の色調、ゆとりのある余白、地図に情報パネルを重ねるレイアウトを参考にしています。

## 利用者向けの60画面

地図8、検索6、地点詳細6、通報8、避難・防災10、お気に入り6、設定6、ヘルプ10の計60画面。画面上部・下部ナビゲーションの「画面一覧 60」から全画面のカード一覧を開けます。各画面の「前の画面」「次の画面」から60画面を順番に移動できます。各画面は `/#/search` のようなURLを持ち、リンク・戻る・進む・再読み込みに対応します。

**起動後に60画面を確認する：** ブラウザーで `http://localhost:3000/#/sitemap` を開いてください。

[画面一覧と導線](docs/SCREENS.md) / [今回の検証内容](docs/VERIFICATION.md)

- **検索・詳細**：公開された地点の名称・メモを検索し、分類・危険度・対応状況で絞り込み。位置・更新日時・共有リンク・注意点を確認できます。
- **通報**：位置→種類→詳細→確認→送信。SQLiteに非公開で保存され、管理者が確認・公開すると危険箇所の地図に反映されます。受付番号と照会用トークンは送信元のブラウザーに保存します。
- **避難・防災**：災害別の備え、自治体・気象庁等への公式リンク、避難先の個人メモ、持ち出しチェックリスト。警報や避難所開設状況のリアルタイム配信は行いません。
- **お気に入り**：地点・地図の表示エリア・コレクション・検索条件をブラウザー内に保存します。端末間の同期はありません。
- **管理者**：`/admin.html`。既存のログイン、地点登録・編集・削除、対応状況更新、操作履歴、JSON書き出しを維持し、利用者の通報を公開・見送りする機能を追加しました。

## 起動（Node.js 24）

Windowsでは `START-WINDOWS.cmd` のダブルクリックでも依存関係の導入と起動ができます。表示された案内に従い、ブラウザーで `http://localhost:3000/#/sitemap` を開いてください。

```sh
npm ci
npm run build
npm start
```

通常のローカル起動はポート3000、SQLiteと管理者設定は `data/` に保存されます。既存のデータをそのまま読み、新しい通報テーブルを追加する移行です。架空の危険箇所や管理者アカウントは自動作成しません。管理者未設定でも一般閲覧・通報は利用できます。

管理者機能を利用する場合、対話式のターミナルで一度だけ以下を実行し、サーバーを再起動してください。12〜128文字のパスワードを非表示で入力します。平文では保存しません。既存の設定は上書きしません。

```sh
npm run admin:create
```

開発時は `npm run dev:server` と `npm run dev` を別のターミナルで起動します。Viteの `/api` はポート3000に転送されます。依存関係を再導入する際は、自分が起動した開発サーバーを一度停止してください。

## 検証

```sh
npm test
npm run build
npm audit
# 初回のみ、Playwright用のChromiumを導入
npx playwright install chromium
npm run test:e2e
```

OSにChromiumがある場合は、その実行ファイルを指定しても検証できます。

```sh
CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e
```

ブラウザーテストは一時SQLite・一時管理者で独立したサーバーを起動します。実際の `data/` は変更しません。データが空の初回起動でも、全60画面のリンク遷移・各画面固有の本文・「次の画面」による60画面の連続移動をPC・390px幅で検証し、検索・保存・通報・管理者操作も実行します。検証用データは終了時に削除されます。スクリーンショットと結果JSONは `/tmp/machi-browser-artifacts/` に出力します（`ARTIFACT_DIR` で変更可能）。

## 保存と通報の扱い

- 地点・通報・管理者セッション・操作履歴はサーバーのSQLiteに保存します。既存のバックアップ機能で通報も含めて保存されます。バックアップから管理者セッションは除外されます。
- 通報は管理者だけが一覧を閲覧できます。利用者は推測困難な受付トークンで自分の通報を照会します。トークンのハッシュだけをサーバーに保存します。
- ログイン試行制限、CSRF対策、HttpOnlyセッション、入力検証、同時編集の競合保護を維持。通報は接続元IP単位で15分あたり5件まで（プロセス内の制限、再起動でリセット）です。
- お気に入り・検索履歴・通報受付・防災メモ・設定はブラウザー内に保存します。「設定→保存データの管理」で削除できます。受付記録を削除すると通報状況を照会できなくなりますが、サーバー上の通報は削除されません。

## 地図と情報について

地図背景はOpenStreetMapの標準タイルを利用します。通信できない場合は、千代田区周辺の**概略の参考図**を表示します。参考図は道路・避難経路の案内に使用できません。通信制限下でも一覧・詳細・座標入力による通報は利用できます。位置情報は現在地ボタンを押した時に許可を求め、ボタンだけではサーバーへ送信しません。

地図のクレジット表示を保持し、[タイル利用方針](https://operations.osmfoundation.org/policies/tiles/)に従ってください。大規模アクセスやオフラインの一括取得には対応しません。配信元へのネットワーク許可と、有効なTLS接続が必要です。

登録・通報する名称・メモ・位置には個人名、自宅の特定につながる情報、非公開の連絡先を含めないでください。このサイトの通報は警察・消防への連絡ではありません。緊急時は110・119に連絡し、災害時は最新の公的情報を確認してください。

## Webへの公開

具体的な手順は [DEPLOY.md](DEPLOY.md) を参照してください。Docker Compose + CaddyによるHTTPS対応です。利用者向けと管理者向けの両ページをビルドし、データは名前付きボリュームに保持します。HTMLだけの静的ホスティングではデータ共有・通報・ログイン機能は動作しません。

管理者は地域の運営担当者向けの共通アカウントです。一般利用者の個別アカウント、通知、写真添付は含みません。SQLiteを使う単一サーバー構成のため、同じボリュームを複数のアプリサーバーで共有しないでください。DB・バックアップ・管理者ハッシュは機密ファイルとして扱い、Gitや公開ディレクトリに置かないでください。
