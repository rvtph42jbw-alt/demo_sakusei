# 追加企画書を反映した画面遷移図（設計案）

出典：提供資料「＜追加＞企画書_地域危険箇所マップ・安全管理システム_Dチーム.xlsx」の「企画書」シートA8、A10（第1〜20項）。書式は、先に提供された「画面遷移図 (1).xlsx」の白い四角・黒い矢印・機能別シートに合わせています。

- 編集用Excel：`releases/machi-safety-transition-proposal.xlsx`（31シート）
- 印刷用PDF：`releases/machi-safety-transition-proposal.pdf`（A3横・48ページ）
- 一式：`releases/machi-safety-transition-proposal.zip`
- 構造化した設計データ：`docs/flowcharts/proposal-design.json`

## 反映した主な変更

一般ユーザー、組織管理者、システム管理者の3区分へ整理しました。一般登録とメールOTP、規約同意、管理者の招待・承認、管理者MFA、再同意とメニュー分岐を記載しています。

写真付き報告と位置候補の確認、複数カテゴリ、修繕の自治体直送、改善要望の自治会経由、要望の採用・保留・却下と取りまとめを追加しました。

点検の担当・予定・期限・結果・写真・過去比較、優先度候補と自治体による最終確定、修繕・改善、前後写真、住民への回答・完了メッセージ、変更履歴、再点検と再対応を連続した流れにしています。

避難所・避難経路・危険箇所の関連、私有地の所有者確認・連絡・改善依頼も追加しています。所属組織の境界と、権限のある自治体担当者だけが所有者情報を閲覧できる制限は、独立した図にしました。

組織・担当部署、管理者発行・権限、振り分けルール、カテゴリ、重要操作・個人情報アクセスの監査も記載しています。お気に入り、端末設定、ヘルプ、防災ガイドの既存補助32画面は別図に保持しています。

## 設計と実装の区別

70操作を選択・確認・終了で整理し、85件の新設計の画面定義と既存補助32画面を区別しています。共通確認・共通処理結果は再利用します。操作の3段階をすべて独立した画面として数えるものではありません。IDは本設計版で再採番しています。

この資料は追加企画書に基づく設計案であり、機能の実装完了を示しません。企画書はPythonとDjangoまたはFlaskを想定していますが、現行アプリはNode.js/Expressです。今回の作業でアプリ本体を改修・移行してはいません。

優先度の配点・重み・閾値、認証の具体値・MFA方式、振り分けの例外、公開範囲、組織間共有、状態遷移の許可、写真制限、技術選定等は確認事項に残しました。企画書にない数式・数値を確定させていません。AI APIは使用しない設計です。

## 確認内容

追加企画書の全20項目を要件対応表に対応付けました。Excelの全31シートと詳細操作図を描画して確認し、結合セルの重複、エラー値がないこと、117件の画面定義・70操作が収録されていることを確認しました。

PDFは48ページで、全画面IDと操作ID、70操作の補足文、現行実装との差分と未確定事項が欠けていないことを検証しました。Windows版Excelによる実機の操作・印刷は未実施です。
